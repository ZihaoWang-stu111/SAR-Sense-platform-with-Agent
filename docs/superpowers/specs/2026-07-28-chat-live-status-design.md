# 聊天实时加载状态设计

## 目标

用户发送消息后，在 assistant 回答区域显示旋转指示器和简短实时状态，替代当前只有闪烁光标的空白等待体验。状态用于说明系统当前所处阶段，但不替代已有的详细思考过程。

## 交互方案

采用“行内状态”：

- 转圈图标与状态文字显示在最终回答将要出现的位置。
- 不新增卡片、抽屉或独立进度面板。
- 第一段最终回答正文到达时，立即移除转圈和状态文字，并在原位置开始显示正文。
- 加载状态仅存在于当前流式请求的前端内存中，不写入数据库，不出现在历史会话中。

## 状态规则

| 触发条件 | 显示文字 |
|---|---|
| assistant 空消息刚创建 | 正在等待处理... |
| Agent 工作线程开始执行 | 正在思考... |
| 调用 `rag_summarize` | 正在检索知识库... |
| 调用 `web_search` | 正在搜索网络... |
| 调用 `detect_ships` | 正在检测图像... |
| 调用文件解析工具 | 正在解析文件... |
| 调用其他工具 | 正在调用工具... |
| 收到工具结果 | 正在整理结果... |
| 收到 `final_answer` 思考步骤 | 正在生成回答... |
| 收到第一段 `chunk` | 立即隐藏加载状态 |
| 收到 `done` 或 `error` | 强制隐藏加载状态 |

线程池中等待的请求保持“正在等待处理...”。`run_agent()` 真正开始后，后端发送一次 `status` SSE 事件，将状态切换为“正在思考...”。

## 数据流

```text
前端创建空 assistant 消息
    ↓ loadingStatus = "正在等待处理..."
后端执行器开始运行 run_agent()
    ↓ event: status
前端显示 "正在思考..."
    ↓
thought_step(tool_call / tool_result / final_answer)
    ↓
前端映射为检索、搜索、检测、整理或生成状态
    ↓
event: chunk（第一段最终回答）
    ↓
loadingStatus = null，移除转圈，显示正文
```

详细思考过程继续由现有 `thought_step` 渲染。实时加载状态只读取这些事件并生成更短的用户提示，不改变思考步骤的数据结构。

## 后端改动

在 `api/routers/chat.py` 中：

- `run_agent()` 开始执行时向当前请求的 `sse_queue` 写入 `status` 事件。
- SSE 生成器增加 `event: status` 输出分支。
- 不修改 Agent、RAG、数据库和消息持久化结构。

状态事件只表示任务已经从线程池开始执行。检索、工具执行、最终回答等细分阶段继续由现有 `thought_step` 驱动，避免重复设计一套后端状态协议。

## 前端改动

在 `js/chat.js` 中：

- 新建 assistant 消息时增加临时 `loadingStatus`。
- 解析 `status` SSE 事件。
- 根据 `thought_step.step_type` 和 `tool_name` 更新状态。
- 收到第一段非空 `chunk` 时清空 `loadingStatus`。
- 收到 `done`、`error` 或请求异常时清空 `loadingStatus`。
- 渲染空 assistant 消息时输出加载状态行；正文出现后不再渲染该状态。

在 `css/style.css` 中：

- 增加固定尺寸的圆环 spinner。
- 增加低干扰的状态文字样式。
- 支持 `prefers-reduced-motion`，用户关闭动画时停止旋转。
- 加载行尺寸保持稳定，避免正文出现时产生明显布局跳动。

## 异常与边界

- 请求进入线程池排队时，前端持续显示“正在等待处理...”。
- SSE 建立失败、解析失败或返回错误时，停止动画并进入现有错误展示流程。
- 如果先收到 `rag_result`、后收到最终回答，状态切换为“正在生成回答...”，但仍在第一段正文到达时隐藏。
- 历史消息没有 `loadingStatus`，因此刷新页面后不会出现虚假的加载动画。
- 同一页面存在多个会话流时，状态保存在各自的 assistant 消息对象中，不使用全局状态。

## 验证

- 线程池排队期间显示“正在等待处理...”。
- Agent 开始运行后显示“正在思考...”。
- RAG、Web、检测和普通工具调用显示正确状态。
- 第一段回答出现时 spinner 立即消失。
- `done`、`error` 和网络异常不会留下永久转圈。
- 历史会话加载后不显示状态。
- 现有思考过程、参考来源、打字机效果和 SSE 事件保持正常。
- `node --check js/chat.js` 和相关 Python/前端测试通过。
