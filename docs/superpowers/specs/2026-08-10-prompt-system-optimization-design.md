# SAR-Sense Prompt 系统优化设计

## 目标

重写 `main_prompt.txt`、`report_prompt.txt` 和 `research_prompt.txt`，解决当前规则重复、优先级模糊、工具过度调用和历史任务被重复执行的问题，同时保留现有动态 Prompt、研究子 Agent 与前端执行轨迹。

本次只调整 Prompt，不修改 Agent、工具、SSE、数据库或前端代码。

## 已确认原则

1. 每轮只把最后一条 `user` 消息视为当前任务，历史消息仅用于理解上下文。
2. 对话回顾、寒暄、改写、解释已有内容等请求直接回答，禁止调用工具。
3. 已完成的历史任务不得重新执行，除非最新消息明确要求刷新、重试或重新查询。
4. 工具调用前只输出一句简短行动说明，不要求展示内部推理过程。
5. 单轮工具调用上限统一为 6 次；报告和研究任务同样不超过 6 次。
6. 工具描述以实际能力为准，例如 `get_weather` 只查询实时天气，不承担未来天气预报。

## 三层 Prompt 职责

### main_prompt.txt

主 Prompt 负责普通对话和意图路由，按以下优先级处理：

1. 最新消息与历史边界。
2. 无工具即可完成的请求。
3. 用户明确要求的本地检索、联网搜索、报告、检测或指标计算。
4. 复杂研究、本地知识、业务数据、天气海况、图像检测等意图路由。
5. 工具结果检查、停止条件和最终回答。

主要路由规则：

- 对话回顾、寒暄、文本改写和基于已有上下文的追问：直接回答。
- 三个及以上研究对象、跨文档综合或用户明确要求深入研究：调用一次 `delegate_research`。
- SAR 专业知识、论文、人物和已上传文件内容：优先 `rag_summarize`，证据不足时再按需 `web_search`。
- 用户明确要求联网或最新信息：直接 `web_search`。
- 当前天气：`get_weather`；未来天气：`web_search`；未给城市且指向当前位置时先 `get_user_location`。
- 场景记录、趋势和比较：分别使用对应数据工具，不重复获取用户已经提供的参数。
- 用户明确要求生成报告：调用 `fill_context_for_report` 进入报告模式。
- 用户提供 TP、FP、FN 并要求计算指标：调用 `calculate_detection_metrics_mcp`。
- 用户明确要求检测已上传 SAR 图像：调用 `detect_ships`；OCR 和普通图片不得误用检测工具。

主 Prompt 不再重复完整参数结构，参数名和类型由工具 Schema 提供，只保留容易混淆的能力边界。

### report_prompt.txt

报告 Prompt 只在 `fill_context_for_report` 已触发后生效，负责：

- 复用用户已经提供的场景 ID 和月份。
- 缺少当前月份时调用 `get_current_month`。
- 获取检测记录，必要时查询趋势、场景比较、海况和专业知识。
- 不猜测城市、时间、指标或缺失数据。
- 数据不足时明确说明局限，而不是重复调用同一失败工具。
- 输出结构化 Markdown 报告与针对性建议。

报告 Prompt 不再承担普通问答意图判断，也不重复主 Prompt 的全部工具说明。

### research_prompt.txt

研究子 Agent 负责跨论文、跨算法和多来源综合：

- 将研究任务拆成少量明确子问题。
- 本地论文和知识库优先使用 `rag_summarize`。
- 本地证据不足、用户要求最新信息或外部资料时使用 `web_search`。
- 多对象分别检索，避免将所有对象塞进一个模糊查询。
- 明确证据一致处、冲突处和资料缺口。
- 不重复相同查询，不虚构论文内容或来源。
- 最终只返回研究结论，不输出内部推理过程。

## 工具执行约束

1. 工具只解决最新用户请求中确实缺失的信息。
2. 能直接回答时不调用工具。
3. 工具结果足够后立即停止。
4. 单个工具失败后不得仅通过改写相同参数反复重试。
5. 本地知识不足不等于所有问题都必须联网；只有回答确实需要外部信息时才兜底搜索。
6. 任何工具不得因为上一轮曾被调用而在当前轮自动重放。

## 输出规则

- 默认使用中文，除非用户指定其他语言。
- 优先直接回答用户问题，不强制附加 SAR 领域分析。
- 不编造工具结果、来源、日期或指标。
- 调用工具前最多输出一句简短行动说明。
- 最终回答不复述工具执行过程，除非用户询问执行链路。
- 用户要求简短回答时严格控制篇幅。

## 验收场景

1. 历史中刚完成天气查询，用户问“我一开始问了什么”时，直接回答历史内容，不调用任何工具。
2. 用户问“济南当前天气”时调用 `get_weather`；问“济南明天天气”时不先调用实时天气工具。
3. 用户给出 TP=80、FP=10、FN=20 时调用 MCP 指标工具。
4. 用户问单篇论文内容时调用本地 RAG，不委派研究子 Agent。
5. 用户比较三个算法时只委派一次研究任务，主 Agent 不再重复 RAG。
6. 用户只问普通概念、改写或历史回顾时不调用工具。
7. 用户明确要求报告时进入报告 Prompt，普通“怎么优化”问题不得误触报告模式。
8. 所有 Prompt 中不存在互相冲突的 5/6/8 次工具调用上限。

## 非目标

- 不新增意图分类模型或硬编码 Python 路由。
- 不改变工具签名和 Agent 注册方式。
- 不调整报告模板以外的前端展示。
- 不通过 Prompt 承诺当前工具并不具备的能力。
