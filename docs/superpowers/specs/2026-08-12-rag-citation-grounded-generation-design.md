# RAG 引用约束式生成设计

## 1. 背景

当前 RAG 已具备以下能力：

- 向量检索与 BM25 多路召回；
- BGE 子块重排及最低相关性阈值；
- 父块回表，为生成模型补充完整上下文；
- 无可靠检索结果时直接拒答；
- 自动追加来源文件、块 ID 和重排分数。

现有链路能够判断“检索结果与问题是否相关”，但不能稳定判断“检索结果是否直接支持回答”。知识库没有答案时，仍可能召回主题相近的背景材料，生成模型容易据此补出看似合理但缺乏依据的答案。

此前尝试的独立 EvidenceGate 会额外拆解问题、逐项检查覆盖度。该方案调用和代码较多，而且容易把可以部分回答的问题整体判为证据不足，因此不再采用。

## 2. 目标

在不增加模型调用的前提下，让 RAG 具备以下行为：

1. 只有资料直接支持的具体结论才允许输出。
2. 每个关键结论必须带有可追溯的证据编号。
3. 资料只能回答部分问题时，保留有依据的部分并明确指出缺失信息。
4. 只有相关背景、没有直接答案时，明确说明“当前资料没有明确说明”。
5. 引用缺失或编号非法时由程序失败关闭，不直接信任模型输出。

## 3. 非目标

本次不实现：

- 独立 EvidenceGate；
- 额外的 LLM 校验调用；
- 问题条件拆解和逐项覆盖率计算；
- Pydantic 结构化输出；
- NLI 或新的重排模型；
- 数据库、向量库及前端结构改造。

## 4. 总体链路

```text
用户问题
  -> 向量/BM25 召回
  -> BGE 相关性过滤
  -> 父块回表
  -> 组装带编号的证据上下文
  -> 现有 RAG 模型一次生成
  -> 程序校验证据编号
  -> 追加现有来源列表
  -> 主 Agent 基于工具结果回答
```

这套方案保留现有“召回相关性门槛”，并把“直接证据判断”合并到原本就存在的回答生成调用中，因此不会增加一次模型请求。

## 5. 证据上下文

`RagSummarizeService` 继续使用父块作为生成上下文，但每个父块被明确包装为一个证据单元：

```text
[证据1]
正文：...
来源：SFQ-Det.pdf | page=3 | chunk_id=...

[证据2]
正文：...
来源：SFQ-Det.pdf | page=0 | chunk_id=...
```

编号只在本次 `rag_summarize` 调用内有效，并与最终自动追加的来源列表一一对应。

## 6. 一次式证据判断与生成

修改 `prompts/rag_summarize.txt`，要求模型在一次生成中遵守以下规则：

### 6.1 证据分类

- **直接证据**：原文明确包含所需结论、数值、关系或表格行，可以用于回答。
- **背景信息**：只说明主题、定义或相近内容，不能用于推导用户所问的具体结论。
- **信息缺失**：资料未明确说明，必须指出缺失，不得根据常识或模型记忆补全。

### 6.2 回答策略

- 资料完整：回答问题，并在关键结论后引用证据。
- 资料部分完整：回答有直接证据的部分，同时明确指出无法回答的部分。
- 只有背景信息：说明现有资料提到了什么，以及没有明确说明什么。
- 完全无直接证据：回答“当前资料没有明确说明该问题，无法基于知识库可靠回答”。

### 6.3 证据不足控制标记

完全没有直接证据时，模型必须以内部标记 `[[INSUFFICIENT]]` 开头。服务层校验后移除该标记，只向用户展示后面的自然语言说明。

部分可回答不使用该标记，而是正常输出有引用的结论，并在正文中说明缺失部分。

### 6.4 内部引用格式

模型使用不会与普通论文编号混淆的内部标记：

```text
SFQ-Det 在 SSDD 上比 YOLOv8 提升 2.5 个百分点 [[EVIDENCE:1]]。
```

通过校验后，服务层再把它转换为用户可读的 `[1]`。

表格可以在表格标题、引导句或表格后统一引用对应证据，不强制每个单元格重复标注。

## 7. 引用完整性校验

在 `rag/rag_service.py` 中增加少量确定性校验，不新增独立服务类。

校验规则：

1. 提取回答中的全部 `[[EVIDENCE:n]]`。
2. 每个 `n` 必须落在当前证据编号范围内。
3. 以 `[[INSUFFICIENT]]` 开头的回答允许没有引用；服务层移除该控制标记后返回其自然语言说明。
4. 其他回答必须至少包含一个有效引用，否则统一降级为安全提示。
5. 出现非法编号或格式损坏时，不返回模型原回答，统一降级为安全提示。
6. 校验通过后，把内部引用转换为 `[n]`，再沿用现有来源列表格式。

安全降级文案：

```text
当前资料不足以直接支持可靠结论，无法基于知识库回答。
```

该校验能保证引用存在且指向真实召回证据，但不声称能够用纯代码证明语义蕴含关系。直接支持关系仍由生成模型在提示词约束下判断，这是“不增加第二次模型调用”的明确边界。

## 8. 主 Agent 约束

在 `prompts/main_prompt.txt` 增加两条规则：

1. `rag_summarize` 已指出信息缺失时，必须保留该结论，不得使用模型自身知识补全。
2. 基于 RAG 回答时保留其证据引用，不新增工具结果中没有的事实。

用户明确限制“只能使用本地知识库”时，继续禁止使用 `web_search` 补全。

## 9. 示例行为

用户提问：

```text
SFQ-Det 在 SSDD 和 HRSID 上分别比 YOLOv8 提升多少 mAP，并解释原因？
```

如果知识库只有 SSDD 数值和结构原理，预期回答为：

```text
SFQ-Det 在 SSDD 上比 YOLOv8 提升 2.5 个百分点 [1]。

当前资料没有给出 SFQ-Det 与 YOLOv8 在 HRSID 上的完整 mAP 对比数据，
因此无法计算 HRSID 上的提升幅度。

其性能提升主要来自结构调制、小波池化和质量感知检测头 [2]。
```

缺少 HRSID 证据不会导致整题拒答，也不会允许模型编造 HRSID 数值。

## 10. 修改范围

- `prompts/rag_summarize.txt`
  - 增加直接证据、背景信息、部分回答和内部引用规则。
- `rag/rag_service.py`
  - 调整证据上下文标签。
  - 校验并转换内部引用标记。
- `prompts/main_prompt.txt`
  - 要求主 Agent 保留 RAG 的引用和信息缺失声明。
- 测试
  - 覆盖有效引用、非法引用、无引用回答、部分回答和纯证据不足回答。

## 11. 验收标准

1. 有直接证据时正常回答并显示 `[n]`。
2. 部分证据存在时能够部分回答，不做整题拒答。
3. 只有相关背景时明确说明资料未直接回答。
4. 模型引用不存在的证据编号时安全降级。
5. 模型给出正面事实但没有引用时安全降级。
6. 不增加 LLM 调用次数。
7. 现有检索材料和参考来源折叠面板继续正常工作。

## 12. 已知边界

该方案比单纯提示词多了一层引用完整性校验，但仍不是严格的语义蕴含证明。如果后续评测发现模型经常把“相关背景”错误引用为直接证据，再考虑增加短答案事实核验调用；当前阶段不提前引入该复杂度。
